# Phase 8 — UI Design Contract

> Visual and interaction contract for New Vault UI (Figma Port). Generated by gsd-ui-researcher,
> verified by gsd-ui-checker. Scope is narrowed per `8-CONTEXT.md`'s `<domain>` boundary: this is a
> **visual/interaction port** of the existing 54-command backend into a Figma-derived three-pane
> shell, shipped as a toggleable second frontend (`newui.html`) — not the item-types/favorites/
> folders/per-item-health feature build the original ROADMAP.md goal text described. Favorites,
> folders, item-type filters, the type picker, sync, and the History tab are explicitly OMITTED
> (CONTEXT.md D-10) — do not design for them.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: Tailwind's `.5`-step utilities (2px/6px/10px/14px — e.g. `px-2.5`, `gap-2.5`) are
permitted ONLY for icon-adjacent micro-spacing inside dense chrome (`ItemRow` vertical padding,
`Sidebar` logo gap, icon-chip internal padding) — mirrors the Figma reference's own use of these in
exactly those spots. All section-level and layout-level spacing (pane padding, gaps between
cards/fields, modal padding) must snap to the 4px scale above. Layout widths are fixed, not on the
spacing scale: Sidebar 220px (≥1024px) / icon-rail width unchanged from today's `NavRail` at
640-1023px, ItemList 280px, DetailPanel flex-1 (D-18).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 600 (semibold) | 1.4 |
| Body | 14px | 400 (regular) | 1.5 |
| Heading | 16px | 600 (semibold) | 1.2 |
| Display | 20px | 600 (semibold) | 1.2 |

Only two weights in this phase: 400 regular (body text, field values) and 600 semibold (labels,
headings, buttons) — no 500/700. Label role additionally gets `uppercase tracking-widest` (matches
the Figma `DetailField`/section-label pattern, bumped from its 10px to 12px here for legibility).
Display (20px/600) is already the existing convention for top-level screen headings (`text-xl
font-semibold`, e.g. `Vault.tsx`'s `<h1>Vault — {username}</h1>`) — the reused secondary panes
(Generator/Health/Data/Trash/Settings) already use it internally; no restyling needed there. Heading
(16px/600) is for this phase's own new chrome: `ItemList` pane title, `DetailPanel` site-name
header, `Sidebar` "Vault" label.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` → `#f8fafc` light / `#0f172a` dark | App shell background, `DetailPanel` empty-state background |
| Secondary (30%) | `var(--surface)` → `#ffffff` light / `#1e293b` dark, paired with `var(--border)` → `#cbd5e1` light / `#334155` dark for hairlines | `Sidebar`, `ItemList` panel, `DetailPanel` content cards, `CredentialBlock`/`PaneSurface`, modal overlays |
| Accent (10%) | `var(--accent)` — default indigo `#6366f1` / hover `#4f46e5`; **user-selectable across 5 hues (indigo/sky/teal/purple/pink) via the existing picker — never hardcode a hex** | Primary CTA buttons ("Add site" +, "Add credential", Unlock/Login submit), selected `Sidebar` nav item + selected `ItemRow` (via `var(--accent-subtle-bg)`/`var(--accent-subtle-fg)` tint, not a solid fill), input focus rings, site-url hyperlink |
| Destructive | `var(--danger)` → `#dc2626` light / `#ef4444` dark, hover `var(--danger-hover)` → `#b91c1c` light / `#f87171` dark | Delete-site button/icon, Purge-Trash button — destructive actions only |

Accent reserved for: the "Add site" and "Add credential" buttons, the Unlock/Login submit button,
the selected Sidebar nav item, the selected ItemList row, input focus rings, and the site-url
hyperlink. Never for item icons, badges, the reprompt indicator, or any other decorative use.

This phase deliberately keeps the existing 5-option accent picker rather than adopting the Figma
mockup's single fixed `#175ddc` — CONTEXT.md D-13 already settles this ("do NOT port the mockup's
DARK/LIGHT JS maps... which doesn't compose with the real 5-accent picker"), resolving the open
question flagged in STATE.md's Deferred Items table. The per-item health strength meter's
"strong"/success color has no existing semantic token (`App.css` only aliases `--danger` and
`--warning` from Tailwind's red/amber ramps) — use Tailwind's `--color-green-600` (light) /
`--color-green-400` (dark) theme variables directly, the same aliasing pattern `App.css` already
uses for danger/warning, rather than adding a new custom property for one component.
