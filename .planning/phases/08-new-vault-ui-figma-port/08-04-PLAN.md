<objective>
Build the detail column: a site's header, notes, and one block per credential with reveal,
copy, TOTP, custom fields and a live strength meter.

Purpose: this is where the vault's secrets actually surface, so it is where every
cross-cutting security behaviour has to land correctly — reprompt on both reveal and copy,
for both the secret and hidden custom fields; a fixed-width mask; decryption that happens
only for the selected site and is dropped the moment the vault locks.

Output: `DetailPanel`, `CredentialBlock`, `DetailField`, `CopyButton`, a tested pure module
for the repeater's zero/one/many rule and the meter mapping, and the `NewShell` wiring that
puts the panel in the detail column.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Decrypted credential → DOM | This plan is the only place plaintext secrets reach the renderer's DOM. Reveal, copy and the strength call all operate on that plaintext. |
| Reprompt flag → reveal/copy gate | `credential.reprompt` is the per-item "require master password to view" switch; it must intercept reveal AND copy, on the main secret AND on hidden custom fields. |
| Renderer → OS clipboard | A copied secret lands in a system-wide buffer other processes can read. |
| `vault-locked` event → mounted panel | Unlike the old modal, this panel stays mounted, so a lock must actively evict state rather than relying on unmount. |
