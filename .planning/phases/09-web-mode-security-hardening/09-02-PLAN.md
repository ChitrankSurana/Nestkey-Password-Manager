<objective>
Close the CSV-import half of SECURITY_CONCERNS.md H1 (SEC-01): `read_csv_headers` and
`import_csv_preview` stop accepting a client-supplied path and stop reading the server filesystem.
The browser uploads the file body once; the bytes are cached on that browser's own session and every
downstream step reads from the cache.

Purpose: these two handlers are H1's arbitrary-file-**read** primitive — `read_csv_headers` returns
file contents as headers and `import_csv_preview` returns file contents as records, so any
authenticated web session could read `~/.ssh/id_rsa` through them today. Removing the path parameter
removes the primitive structurally (D-01).
Output: an `UploadCache` on `UserSession`, a raw-bytes `/api/upload_csv` route with a route-scoped
body limit, path-free core parse functions, an `httpUpload` transport helper, a file-input branch in
`CsvImport.tsx`, and integration tests covering the happy path, the cross-session isolation, the
no-upload case, the concurrency guarantee and the cache lifecycle.
</objective>

## Planner Decisions (Claude's Discretion, recorded here)

- **Raw request body, not `axum::extract::Multipart`** (resolves 09-RESEARCH.md Open Question 3):
  zero new Cargo dependencies, and this flow never bundles the file with other form fields — the
  format selection is a separate JSON call per D-03.
- **`UPLOAD_BODY_LIMIT = 25 * 1024 * 1024`** applied as a per-route layer on the upload routes only,
  never on the whole router — axum's 2 MiB default (RUSTSEC-2022-0055) would silently reject a real
  vault-sized CSV, and widening it globally would loosen every JSON command route too.
- **Cached bytes are held in `zeroize::Zeroizing<Vec<u8>>`** (the crate is already a `web-src-tauri`
  dependency) so the plaintext credentials in an uploaded CSV are wiped when the cache is cleared.
- **The upload cache is a single slot, not a per-kind map.** A `Backup` upload replaces a pending
  `Csv` upload and vice versa. One user-driven file operation is in flight at a time in both screens,
  and a single slot makes "cleared on commit / cancel / logout" trivially auditable.
