## Planner Decisions (Claude's Discretion, recorded here)

**The production policy string** (D-15 locks the first three directives verbatim; the rest are the
delegated discretionary directives, each grounded in what this repo actually loads):

```
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
```

| Directive | Why this value is safe for this repo |
|---|---|
| `script-src 'self'` | Vite emits only external module scripts; there are no inline script tags, so no nonce machinery is needed. |
| `style-src 'self'` | The one inline-style call site (`src/components/PasswordGeneratorPanel.tsx`, the strength-meter width) is a React DOM *property* assignment, not parsed inline CSS text, so it is unaffected. Tailwind v4 compiles to a same-origin stylesheet. |
| `img-src 'self' data:` | `index.html` references only `/vite.svg`; the data scheme covers inline icon data URIs. |
| `connect-src 'self'` | Every API call is a same-origin `fetch("/api/...")`. The Have I Been Pwned check runs server-side in `pwmgr-core`, not from the browser. |
| `font-src 'self'` | `bootstrap-icons` is bundled locally via an npm dependency and a CSS import, not a CDN. |
| `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'` | Standard hardening defaults with no conflicting usage in this codebase; `frame-ancestors 'none'` is the CSP-native complement to the `X-Frame-Options` header D-18 requires. |

**The other three headers** (D-18): `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`
(simplest defensible choice — a loopback-only server has no legitimate cross-origin referrer need),
and `X-Frame-Options: DENY`.

**The web server needs no dev/prod split.** `pwmgr-web` only ever serves the built `./dist` bundle —
it has no Vite-proxying mode of its own — so the strict policy is sent unconditionally.

**D-17's premise does not hold, and this plan introduces the mechanism it assumed existed.**
09-CONTEXT.md D-17 says to "gate this on the same dev/prod signal the codebase already uses."
09-RESEARCH.md verified that **no such signal exists**: there is no dev config file, no `--config`
flag in any npm script, and no environment-gated Rust path in `src-tauri/`. Tauri v2 CSP applies
during `tauri dev` as well as in release builds, so a split is genuinely required, not optional. This
plan therefore introduces Tauri's own documented mechanism fresh: a `src-tauri/tauri.dev.conf.json`
overlay applied as an RFC 7396 JSON Merge Patch via the CLI's `--config` flag. Record this in the plan
SUMMARY as the resolution of 09-RESEARCH.md Open Question 1.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Injected script → DOM + IPC | An XSS sink in the SPA runs with access to decrypted secrets in the DOM and, on desktop, to the whole Tauri IPC surface. CSP is the boundary that keeps that script from loading or executing. |
| Browser content sniffing → served asset | Without nosniff, a response the browser re-types as script becomes an execution path. |
| Third-party page → framed app | A hostile page framing the running app for clickjacking. |
| Development config → production build | A relaxed policy leaking into a release build silently removes the protection this plan adds. |
