# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Enabling Settings → SSH Agent → "Enable SSH agent" crashes `pwmgr-app.exe`. Root cause is now **confirmed** (not just suspected): a raw `tokio::spawn` call at `src-tauri/src/ssh_agent_service.rs:138` panics with "there is no reactor running, must be called from the context of a Tokio 1.x runtime" because it runs on Tauri's native main/webview thread with no ambient Tokio reactor — both from `.setup()` at boot and from the synchronous `update_ssh_agent_enabled` command. The same panic explains both a clean exit-101 (seen in a live repro this session) and the earlier `0xc0000409` fastfail crash-loop (timing-dependent UB when a Rust panic unwinds across the native GUI/WebView2 FFI boundary). The fix (`tokio::spawn` → `tauri::async_runtime::spawn`) is known, one line, and was verified to compile clean in a throwaway edit — but **not applied or committed**, per the plan's own rule that no fixes land before joint review of all findings. Do not re-enable the toggle without a plan, and do not apply the fix without checking with the user first.
- [ ] CONSTRAINT: Make UI's item list ("All Items" and everything derived from it) can go stale after `Restore Backup`'s forced relogin and not self-correct until a genuine Add Item call forces a refetch. If you see a suspiciously low/zero item count or a "Vault is locked" banner in Make UI, do NOT conclude data loss — add a throwaway item first to force a refresh, then re-assess.
- [ ] CONSTRAINT: Clicking Lock in Make UI (web mode) or the read-only Viewer app does not tear down the UI — a stale, still-interactive screen with revealed secrets can persist until a hard reload. Known (`M3.6-lockbug`, `M13.3-viewer-lockbug`), not yet fixed.
- [ ] CONSTRAINT: The documented Viewer-app dev launch command (`cd viewer-src-tauri` then `npx tauri dev`) fails on this machine — `beforeDevCommand` runs with cwd = repo root instead of `viewer-src-tauri`, so `npm --prefix ..` resolves one directory too high. Workaround: run `npm run dev` from repo root in one terminal, then from `viewer-src-tauri` run `npx tauri dev --config <path-to-a-file-containing>` `{"build":{"beforeDevCommand":""}}` — inline JSON via `--config` gets mangled by `npx.cmd`/PowerShell quoting, must use a file. Logged as `D-viewer-launch` in the findings doc, not yet fixed at the source.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| A literal newline inside a markdown table cell silently breaks the table | Hit this once already during the first ledger→findings-doc merge: multi-line user notes inserted with real `\n` characters split the table row across multiple lines, corrupting the file | blocking | Always flatten any multi-line text (`\n` → space) before inserting it into a markdown table cell. Verify after any bulk edit that every content line still starts with `\|` and has the expected column count |
| Assuming a "Vault is locked" banner or 0-count means real data loss | Multiple distinct bugs across sessions all produce the same visual symptom, most cosmetic | advisory | Cross-check against Classic UI on the same vault, or add a throwaway item, before concluding data is missing |
| PowerShell mangles inline JSON passed to `npx`/`.cmd` wrappers | `--config '{"a":"b"}'` and even backslash-escaped variants get their quotes stripped before reaching the Rust binary | advisory | Write the JSON to a temp file and pass `--config <file>` instead of inline JSON, whenever shelling out to a `.cmd`-wrapped tool from PowerShell |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
