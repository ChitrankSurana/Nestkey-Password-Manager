## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Silently reinterpreting an existing DB column's meaning | B7 needed the per-credential reprompt flag's meaning inverted; reusing the old `reprompt` column under the new meaning would have silently un-protected any credential a user had previously flagged true | blocking | Add a NEW column with a safe default (0/false for everyone, old and new rows) instead of reinterpreting an existing column's stored values, whenever a boolean's *meaning* flips |
| Assuming `cargo build` success means `cargo test` will pass | This session repeatedly had `cargo build --workspace` succeed while a specific new test still failed (wrong destructuring, a bad Luhn-test fixture with no required padding, etc.) | advisory | Always run the actual new/changed tests (`cargo test -p pwmgr-core --lib <name>`) before assuming a build-clean commit is test-clean, especially on this machine where a full `cargo test --workspace` run takes 1.5–2 minutes |
| Piping `cargo test` output through `grep` in a backgrounded shell command | `grep` (not `--line-buffered`) fully buffers when its stdout isn't a tty, so the output file stays empty for the whole ~2 minute test run, not just briefly | advisory | Either don't pipe through grep in a background call (redirect raw output and grep the file afterward), or accept the output arrives all at once near the very end - don't read an empty output file as "nothing happened yet" without checking whether the process itself has exited |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
